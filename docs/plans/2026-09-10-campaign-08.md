# Campaign 08 — did the criteria fix work? Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task.
> On execution, copy this file to `docs/plans/2026-09-10-campaign-08.md` and commit it —

**Goal:** Measure whether weighting instruction-adherence 3/4 (PR #69) removes the
instruction-following regression that campaign 07 reproduced across two model families —
with enough repeats that the answer is attributable rather than noise.

**Architecture:** One model, two criteria conditions, two repeats each, run concurrently in
two batches with a control arm per batch. The only difference between conditions is the
`sampler_config.json` GEPA reads, which is selected by agent-module name — so the baseline
condition is a second agent directory, not a flag.

**Tech Stack:** Python 3.11, `uv`, Vertex AI Managed Pipelines, `scripts/run_campaign.py`.

---

## Context

Campaign 07's one solid result: across `claude-sonnet-5` and `gemini-3.1-pro-preview`, GEPA
improved `safety_v1` (a criterion it is scored on) and degraded `instruction_following_v1`
(the metric absent from its criteria). Those were the only two effects that survived both
the noise floor and the run-to-run spread.

PR #69 acted on it — instruction adherence went from 1 of 2 rubrics inside
`rubric_based_final_response_quality_v1` to 3 of 4 — because `instruction_following_v1`
itself is **not in ADK's metric registry** and naming it raises `NotFoundError`. That change
has never been tested.

Two constraints from campaign 07 decide the shape:

- **Run-to-run spread reached 12.3× the control floor.** Two runs of one manifest disagreed
  on the *sign* of three metrics. So a single arm per condition cannot attribute anything,
  and a between-campaign comparison against c07 is worse still — PR #59 has since removed
  ~14% toolless contamination, so the substrate has moved.
- **The control floor does not transfer.** CLAUDE.md forbids reusing an earlier campaign's
  floor; c07 ran a control per batch and this does the same.

**Supersedes:** `docs/doe/08-gepa-budget-curve.md`, which is pre-registered as campaign 08
but assumes one arm per budget. Its own outcome table already says *"non-monotonic → search
variance dominates budget at this scale, so single-arm sweeps of any budget are not
interpretable"* — c07 measured exactly that, so it would answer itself before running.
Renumber it to 10 rather than delete it; the question is still good, it just needs repeats.

### How the criteria are selected (the mechanism this plan hangs on)

`components.py:592-600` derives the config from the agent module name:

```
agent_module  examples/multi_model_agents/agents/sonnet_agent
  stem        "sonnet"                    (strips "_agent")
  opt_dir     agents/sonnet_opt/
  criteria    agents/sonnet_opt/sampler_config.json
```

So a second condition needs a second agent module. That also gives it a distinct `run_id`
(hashed from manifest name + agent module + eval data + pair ids), so the two conditions
cannot overwrite each other's artifacts.

**Repeats need distinct manifest `name`s** for the same reason — two submissions of one
manifest share a `run_id`, and while PR #66 now archives the predecessor, the live prefix
still holds only the last. `c08-new-r1` / `c08-new-r2` gives each repeat its own prefix.

## Task 5: Pre-register, before running anything

**Files:** create `docs/doe/08-criteria-holdout.md`; renumber the budget curve to
`docs/doe/10-gepa-budget-curve.md` and update `docs/doe/README.md` and
`docs/notes/README.md`

**Primary outcome:** Δ`instruction_following_v1` (eval_after − eval_before), per arm.

**Effect:** mean Δ over the two `new` arms minus mean Δ over the two `old` arms.

**The effect counts only if it clears both bars:**

1. **> 0.017** — the within-condition spread measured on c07's accidental repeat of
   `c07-sonnet5` (IF: −0.045 vs −0.062).
2. **> the c08 control floor for IF**, from this campaign's own two control arms.

**Stopping rule:** if either control's IF drift alone exceeds 0.017, stop and report that
the substrate cannot resolve this effect. Run the controls first, as a gate.

**Secondary, and reported whether or not it is asked for:** Δ`safety_v1`. If the new
criteria shrink the IF regression *and* shrink the safety gain, that is a trade rather than
a fix, and it is the more useful finding.

| Outcome | Reading |
| --- | --- |
| IF regression shrinks, safety holds | The criteria were miscalibrated. Adopt 3/4 and re-baseline |
| IF regression shrinks, safety shrinks too | A real trade, not a bug. Weighting moves it, it does not remove it |
| No difference beyond 0.017 | Rubric weighting is too indirect a lever; the metric needs to be a criterion, which ADK does not allow |
| Within-condition spread > between-condition | n=2 is still too few. Report the variance and stop designing around single runs |

## Risks

- **n=2 per condition bounds variance, it does not measure it.** The decision rule uses a
  spread borrowed from c07's single accidental repeat. If c08's own within-condition spread
  comes out larger than 0.017, the pre-registered bar was too low and the honest answer is
  "unresolved" — say so rather than re-deriving the bar from the data it is judging.
- **Two agent directories can drift.** Task 2's guard is what stops the baseline quietly
  becoming a second copy of the treatment.
- **~22–26 h of wall clock**, mostly optimize (87%). Judge RPM is the binding constraint,
  not budget — total spend is roughly $4.
- **`c07-pro`'s larger IF regression (−0.117) is left on the table.** If sonnet's effect is
  marginal, pro is the natural follow-up, and its variance will by then be known.

## Out of scope

- The budget curve — renumbered to campaign 10, unchanged in substance.
- A second model. Two models × two conditions × one repeat is the configuration c07 showed
  to be uninterpretable.
- Changing `max_metric_calls`, `num_runs`, the seed, or the eval set.
