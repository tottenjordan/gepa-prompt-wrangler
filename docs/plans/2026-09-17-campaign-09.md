# Campaign 09 (DOE 12) — does forwarding the judge's rationale help? Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan
> task-by-task. On execution, copy this file to `docs/plans/2026-09-17-campaign-09.md`.

**Goal:** Isolate rationale forwarding (ADK patch 4b) from the writer-model change it shipped
with, measured on a readout that can actually resolve it — collecting silent failure #12's
acceptance measurement on the same run — and run it as a first-class experiment under
`experiments/`, orchestrated by one Vertex AI Pipelines job.

**Architecture:** The campaign is authored as a manifest, materialised into
`experiments/active/c09-rationale/` by `wrangler experiment create`, and executed as **one**
Vertex AI Pipelines job. Its three arms are manifest *pairs* driven by the existing
`dsl.ParallelFor(parallelism=1)`, so they serialize and never contend for the 5 RPM judge.
No local driver, no stagger loop, no stale-ADC failure mode.

**Tech Stack:** Python 3.11, `uv`, KFP v2, Vertex AI Pipelines, GEAP/Agent Engine.

## Context

Three open threads converge on one run, a fourth result reshapes it, and the repo's
experiment conventions decide where it lives.

**1. m01 is confounded.** Its +0.0065 holdout delta shipped three changes at once: rationale
forwarding (patch 4b), `use_merge=True` (patch 7), and the writer moving to
`claude-opus-4-8`. Patch 7 has since been shown **structurally inert** — merge recombines
fields across *multiple* predictors and we optimize one — so the confound is already down to
two. This campaign removes the second.

**2. Silent failure #12's fix is merged but unproven in production.** It needs one real
optimize stage showing `will run without the tools` at **0** against a 12–24% baseline. Any
arm here carries it free.

**3. DOE 03 calibrated the knobs**: `(num_runs=2, score_repeats=2)` — same cost as today's
`(3,1)`, wins or ties on three metrics, never worst.

**4. DOE 03 also rules out the obvious design.** The holdout floor is **0.0152** at best and
m01's effect was **+0.0065** — 0.43× the floor, with measured exponents of 0.20 (`num_runs`)
and −0.06 (`score_repeats`). **No budget these knobs can buy closes that gap.** Hence
`safety_v1` is the primary readout and the holdout is pre-registered as under-powered.

### The convention, and a schema divergence that will bite

Per [experiments/README.md](../../gepa/gepa-prompt-wrangler/experiments/README.md), an
experiment is a directory: `config.yaml`, `doe_plan.md`, auto-generated `manifest.json`,
`stages/`, `reports/`, `images/`. Created from a manifest via `wrangler experiment create`.

**The two YAML schemas are not interchangeable, and nothing says so today:**

| | `manifests/*.yaml` | `experiments/active/*/config.yaml` |
| --- | --- | --- |
| name | top-level `name:` | nested under `experiment:` |
| loader | `PairFactory.load()` (`core/factory.py:118`) | `Experiment.load()` (`orchestration/experiment.py:140`) |
| written by | a human | `Experiment.create()` (`experiment.py:41`) |

Verified: `PairFactory.load("experiments/active/multi-model-v8/config.yaml")` raises
`ValueError: Manifest is missing required field: 'name'`. So Task 5's runner must read the
**experiment** schema, and the campaign is authored as a manifest first.

### Vertex Pipelines guidance worth adopting (researched 2026-09-17)

- **Task-level retries with exponential backoff** (`task.set_retry(...)`). **Used nowhere
  today**, and a 5 RPM judge that already produced 76 × HTTP 429 is the textbook case. Retry
  transient classes only; never a non-idempotent deploy.
- **`parallelism=1` as the quota control** — the documented pattern for limiting concurrent
  calls to a rate-limited service. Already present; this campaign leans on it instead of a
  wall-clock stagger that covers only the first 40 min of a 10 h stage.
- **Small-scale run before the expensive one** — the smoke gate in Task 6.
- **Vertex AI Experiments** (attaching pipeline runs for parameter/metric comparison) is a
  genuine fit for a DOE but **out of scope**: new surface on a campaign that already carries
  three code changes, and `stages/` already holds the numbers.

## The design

| arm (pair id) | `forward_rationale` | optimize? | purpose |
| --- | --- | --- | --- |
| `c09-rationale-on` | **true** | yes | reproduces m01's configuration |
| `c09-rationale-off` | **false** | yes | the contrast — patch 4b off, all else identical |
| `c09-control` | n/a | **no** | noise floor; prompt byte-identical both sides |

Held constant: agent module, writer (`claude-opus-4-8`), judge, sampler config, eval set
(64 cases), `num_runs=2`, `score_repeats=2`, `use_merge` on (inert; leaving it keeps the
comparison to m01 exact).

**Primary readout: `safety_v1`** — floor **0.0082**, measured effects **+0.154/+0.131**,
reproduced within **0.003** across two runs. A between-arm difference above ~0.01 is real at
n=1.

**Holdout (`instruction_following_v1`): reported, pre-registered under-powered.** MDE ≈ 0.0152
against an expected ~0.0065. State the MDE beside every holdout number.

**Thresholds:** the sampler config in the agent's `*_opt/` directory is authoritative and
ignores `config.yaml` thresholds (experiments/README.md, "Common Pitfalls"). Change nothing
there — a threshold change would be a second variable.

## Task 3: Control arms inside the same pipeline job

**Files:** `wrangler/pipeline/components.py` (`optimize_single_agent`) ·
`tests/test_control_arm_in_pipeline.py` (new)

`skip_optimize` is a **pipeline-level** parameter (`dag.py:128`), so a control arm cannot
currently share a job with optimizing arms.

**Do not restructure the DAG.** Branching `dsl.If` on a field of a `ParallelFor` loop item is
fragile across KFP versions. **Short-circuit inside the optimize component**: when the pair
says `skip_optimize`, log why, return `original_prompt` unchanged, make no GEPA calls.
Redeploy and eval_after then run against an identical prompt — exactly a control arm, and
`PairAnalysis.is_control` already detects it via `original_prompt == optimized_prompt`.

1. **Failing test:** a control pair makes zero GEPA calls and returns its prompt byte-identical.
2. Implement the short-circuit at the top of the component body.
3. Assert the pipeline-level `skip_optimize` still works, so existing manifests are unaffected.

⚠️ **Changes a component body ⇒ invalidates KFP's `optimize` cache repo-wide.** Fine here
(`cache_bust` is bumped anyway), but do not merge under a live campaign driver
(silent-failures #13).

**ETA: 45–60 min.**

  Pre-registered so it cannot be written up as evidence of no effect.
- **n=1 per condition.** Defensible for `safety_v1` only; campaign 07 measured 12.3× floor
  spread between two runs of one manifest on other metrics.
- **Task 3 busts the `optimize` cache repo-wide.** Intended; do not merge under a live driver.
- **#12 could return 0 deferrals**, meaning patch 8 never ran — treat as void, not clean.
- **Engines age out ~2026-10-11** and this deploys three more. Reap via the `campaign: c09`
  label as the campaign's last step.
- **Cost constants drifted**: DOE 03 budgeted 2.6/2.8 min per capture/scoring, observed
  ~3.9/~5 on 2026-09-17. The 24 h figure uses the observed rates.
