# Experiments

Design of Experiments (DOE) campaigns for GEPA prompt optimization.

## Directory Structure

```
experiments/
├── active/              # Inflight experiments
├── examples/            # Completed reference experiments with real results
├── my_experiments/      # Personal experiments (contents not tracked by git)
└── README.md
```

| Directory | Purpose | Git Tracked? |
|-----------|---------|:------------:|
| `active/` | Inflight experiments and evaluations | Yes |
| `examples/` | Reference experiments with configs and results | Yes |
| `my_experiments/` | Personal experiments | **No** (gitignored) |

## Experiment Structure

Each experiment directory:

```
my-experiment/
├── config.yaml          # Experiment definition (pairs, defaults, hypotheses)
├── doe_plan.md          # Experiment design (hypotheses, evaluation framework)
├── manifest.json        # Auto-generated stage tracking (status, timestamps)
├── stages/              # Stage output files
│   ├── deploy.json      # Engine IDs per pair
│   ├── eval_before.json # Baseline scores per pair
│   ├── optimize.json    # Optimized prompts per pair
│   ├── redeploy.json    # Redeploy confirmations
│   └── eval_after.json  # Post-optimization scores per pair
├── reports/             # Analysis reports
└── images/              # Charts referenced by reports
```

### Standard Files

- **`config.yaml`** -- Experiment definition: pairs, model configs, hypotheses, phase gates, eval config.
- **`doe_plan.md`** -- Experiment design document: context, hypotheses, evaluation framework, success criteria.
- **`manifest.json`** -- Auto-generated by wrangler. Tracks stage completion, timestamps, per-pair status.
- **`stages/`** -- JSON output from each pipeline stage. Each stage merges results per-pair.
- **`reports/`** -- Comparison reports and analysis. Images referenced via `../images/`.
- **`images/`** -- Charts and diagrams generated by `wrangler report`.

## Running an Experiment

### Create

```bash
# From an existing manifest
wrangler experiment create examples/multi_model_agents/manifest.yaml \
    --name multi-model-v5 --version wrangler_v5

# Check what was created
wrangler status experiments/active/multi-model-v5
```

### Run Stages Individually

Each stage can target a single pair with `--pair`:

```bash
# Deploy all pairs
wrangler deploy experiments/active/multi-model-v5

# Evaluate one pair (baseline)
wrangler eval experiments/active/multi-model-v5 before \
    --pair lite-gemini-3.1-flash-lite --num-runs 3

# Optimize one pair
wrangler optimize experiments/active/multi-model-v5 \
    --pair lite-gemini-3.1-flash-lite

# Redeploy with optimized prompt
wrangler redeploy experiments/active/multi-model-v5 \
    --pair lite-gemini-3.1-flash-lite

# Evaluate post-optimization
wrangler eval experiments/active/multi-model-v5 after \
    --pair lite-gemini-3.1-flash-lite --num-runs 3

# Generate report (needs eval_before + eval_after)
wrangler report experiments/active/multi-model-v5
```

### Run End-to-End

```bash
wrangler run examples/multi_model_agents/manifest.yaml \
    --name multi-model-v5 --version wrangler_v5 --num-runs 3
```

### Check Status

```bash
wrangler status experiments/active/multi-model-v5
```

Shows which stages are complete, which pairs have results, and what remains.

## Conventions

- **Stages are idempotent** -- re-running a stage for a pair overwrites that pair's results
- **Per-pair execution** -- use `--pair <id>` to run one agent at a time
- **Phase gates** -- defined in config.yaml, checked before each stage
- **Auth refresh** -- run `gcert` between stages if tokens expire
- **Reports** go in `<experiment>/reports/`, images in `<experiment>/images/`
